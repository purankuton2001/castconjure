# castconjure — 要件定義書 v0.7
誰でも作れる、生成型フォトリアル AI VTuber

- 版：v0.7（2026-09-04、主語を「配信者」から「生成された推し」へ転換。v0.6 からの差分は末尾）
- 名称：**castconjure**（cast＝配信／配役、conjure＝召喚。推しを唱えて呼び出す）
- 公開チャンネル：YouTube `purankuton2001`
- 種別：個人 OSS（エンジン）＋ 将来のホスト型（推し作成・運用）。MVP 期間は OSS のみ
- 期限：**6 週間で推し 1 体のデモ配信 3 回＋公開**

---

## 1. 目的

### 1.1 何を作るか

誰でも 10 分でフォトリアルな AI VTuber（以下「推し」）を作り、**リップシンクではなく映像そのものを生成して**ライブ配信に載せるツール。推しは待機映像で常時そこにいて、視聴者のコメントが来ると、そのコメントどおりに動く 5 秒の映像が生成されて差し込まれる。

**ポジショニング（一文）**
- 日本語：モデリングもリギングもいらない。顔を 1 回生成して登録すれば、踊る・食べる・喋る・場所を変える推しが、コメントに応えて配信に現れる。OSS・BYOK
- 英語：Photoreal AI VTubers, generated — not lip-synced. Conjure a face once; your fans' comments make her dance, eat, talk, and change scenes, live on your stream. Open source, bring your own key.

**差別化軸（4 つ）**
1. **人形ではなく俳優**：Live2D／リップシンク系は口と首しか動かない。生成型は動作・衣装・場所・カメラが毎クリップ変わる
2. **顔はアプリ内で生成したものだけ**：写真のアップロードを設計上できなくする。「誰でも手軽に」と「実在人物を使えない」を同時に満たし、ディープフェイク製品と一線を引く
3. **二層アーキテクチャで「常時いる」を安く**：事前生成した待機映像プールをループし、反応クリップだけリアルタイム生成。連続生成の 1/6 の費用で常時出演に見える
4. **OSS エンジン × BYOK × バックエンド切替（fal / ローカル H3）**：モデル非依存の配管。データ・費用・炎上リスクは利用者側

**競合との位置（2026-09 時点）**
- リップシンク系アバター（HeyGen、Hedra、Synthesia、Live2D ベースの AITuber、Neuro-sama 型）：固定モデルの口パク。動作と場面は変えられない
- 全画面生成配信（fal.live、Infinite Slop）：画面全体が生成で、固定の人格・顔を持たない
- vid2vid（Daydream / StreamDiffusion、Decart）：人間の演技を別人に変換。演者が必要で、演者の顔が残るリスクがある
- 「固定の推し × 生成型の動作 × コメント駆動 × OBS」を満たす OSS は確認できず。カテゴリは空いている

### 1.2 なぜ作るか

1. 「生成型 AI VTuber」の参照実装として、H3 早期採用層と fal / MiniMax に認知される
2. 推し活の核である「自分の一言に推しが応えた」が、生成型でどこまで成立するかを自分のチャンネルで先に検証する
3. 上記の実績を、後の社内提案・Corecord・独立後の交渉カードにする

### 1.3 作らないもの（明示）

- **写真からの推し作成**（実在人物・他人の顔・既存キャラの持ち込み）。技術的に可能でも UI から外す
- リップシンクモード（MuseTalk 等の口パク合成）。生成型で成立しなければ設計を変える判断はするが、MVP では作らない
- 24/7 の連続生成、汎用 H3 SDK、ComfyUI ノード、3D モデリング、世界モデル的なフレーム操作
- MVP 期間の収益化機能（課金・ギフト連携・ホスト型）。設計で余地は残す
- 会社のコード・データ・アカウント・人間関係を使うもの

## 2. ターゲットと成功条件

### 2.1 ターゲット

| 層 | 求めているもの | 取り込み方 |
|---|---|---|
| 推しを作りたい個人（AITuber 勢、絵もモデルも持たない VTuber 志望） | モデリング不要で、動く・喋る推し | 顔ガチャから配信まで 10 分。OSS |
| ファン（視聴者） | 自分の一言に推しが応える体験 | コメント → 5 秒後に推しが応える。名前が乗る |
| H3 早期採用者（ComfyUI／ローカル勢） | 参照画像で一貫性を出す実運用例、改造できるコード | ローカルバックエンド、待機プールのローカル生成 |
| fal / MiniMax | reference-to-video のリアルタイム実運用事例 | デモ配信映像、顔一貫性・レイテンシ・コストの実測公開 |

### 2.2 成功指標（6 週間時点）

- 推し 1 体でデモ配信 **3 回**（各 60 分以上）。録画と実測ログを公開
- 自分以外が castconjure で推しを作った報告 **3 件**、GitHub Star **100**
- X の初回投稿（推しが動く映像付き）インプレッション **10 万**
- fal または MiniMax と **1 回以上の直接接点**

撤退基準は「3 週目までに推しのデモ配信ができない」こと。1 週目の実測で顔一貫性か台詞が成立しない場合は撤退ではなく設計変更（§9）。

## 3. コアループ

2 つある。

**ループ A：推しを作る（1 回）**
```
顔ガチャ（架空の顔を生成、気に入るまで引く）
  → 参照セットを派生生成（顔アップ／全身／世界観の中に立つ姿）
  → 声サンプル（TTS で生成。実在人物の声は使わない）
  → 人格（名前・設定・話し方・禁止事項）
  → 待機映像プールを事前生成（N 本、ループ用）
```

**ループ B：配信する（常時）**
```
待機映像をループ再生（常時「そこにいる」）
  ↑↓
視聴者コメント
  → 取得（YouTube Live）→ フィルタ（NG・実在人物・レート・承認）
  → （返事モード）LLM が推しの人格で一言返す
  → プロンプト合成（推し参照セット＋世界観＋コメント＋台詞＋音声指示）
  → 生成（fal H3 Max reference-to-video ≈ 3 秒）
  → 反応クリップを差し込み（待機からクロスフェード）→ 「〇〇さんのコメント」を表示
  → 待機に戻る
```

体験の核は「自分の一言で推しが動いた」。生成品質より、反映の可視化と、待機→反応→待機の継ぎ目が自然であることを優先する。

| F-02 | コメント選定 | レート制限、同一ユーザー冷却、`!gen` 接頭辞切替 | ✅ |
| F-03 | NG フィルタ・承認 | 実在人物・性的・暴力・配信者指定語をブロック。無反応。承認モード（`!ok`／UI） | ✅ |
| F-05 | 生成バックエンド抽象 | `generate(prompt, opts) -> clipUrl`。fal（H3 Max t2v / r2v）・ローカル（ComfyUI）・mock。BYOK | ✅ |
| F-07 | キュー | 生成中／待ち／再生中の状態管理、失敗時スキップ、予算上限 | ✅ |
| F-08 | 設定 UI | ローカル Web 画面 | ✅（推し作成を追加） |
| F-09 | 実測ログ | JSONL。受信→生成→再生のタイムスタンプ、コスト、クォータ | ✅（顔一貫性の主観評価タグを追加） |
| **F-10** | **推し作成（顔ガチャ）** | fal の画像モデルで**架空の**顔を生成し、選ばせる。写真アップロード・URL 指定は UI に置かない。選んだ顔から参照セット 3 枚（顔アップ／全身／世界観内）を派生生成し `data/personas/<id>/` に保存。未成年に見える顔・実在の有名人に似た顔は生成側で禁止指示し、生成物は保存前に確認画面を挟む | 新規 |

| **F-12** | **人格** | 名前、設定（年齢感は成人）、話し方、好き嫌い、禁止事項（この推しにさせないこと）。F-04 の「キャラ設定」を置き換える | 新規 |
| **F-13** | **待機映像プール** | 推し作成後に待機クリップを N 本（既定 12、各 5 秒）事前生成。オーバーレイ上でシームレスにループ。ローカルバックエンドでも生成可（無料）。配信中に反応クリップの末尾を待機へ戻すクロスフェード | 新規 |
| **F-14** | **返事モード** | コメントに対し LLM（BYOK、Anthropic / Gemini / OpenAI から選択）が推しの人格で一言（30 字以内）返す。台詞をプロンプトに入れ、オーバーレイに字幕表示。NG フィルタは返事側にもかける。OFF にすると v0.6 と同じ「動作だけ」 | 新規 |
| **F-15** | **二層オーバーレイ** | OBS ブラウザソース 1 枚。下層＝待機ループ、上層＝反応クリップ。切替はクロスフェード、投稿者名と「AI 生成」表記、台詞字幕。反応クリップの再生が終わると待機に戻る | F-06 を拡張 |
| F-04 | プロンプト合成 | 世界観（配信ごと）＋推し参照セット＋人格＋コメント＋台詞＋音声指示。「Image 1 の人物」で参照を指す | ✅（拡張） |

### 4.2 あれば良い（MVP 後）

- 前クリップの末尾フレームを次の `image_url` に渡す連続性（顔と服の一貫性に効くので、1 週目の実測次第で MVP に繰り上げ）
- **ギフト演出権**：スパチャ・ギフトを優先キューと特別演出（衣装チェンジ、場所移動、寄り）に対応付ける。推し活の収益構造そのもの
- 推し同士のコラボ（参照セット 2 体分）
- 配信外への展開：同じ参照セットからショート動画・サムネ・MV を生成するバッチ
- マイク入力（配信者が喋ると推しが反応）
- Twitch / Kick 対応
- ローカル経路のキャラ LoRA（参照画像より強い一貫性）
- ホスト型（推し作成と運用を Web で提供。エンジンは OSS のまま）

## 5. 非機能要件

| 項目 | 要件 | 根拠 |
|---|---|---|
| 反応レイテンシ | コメント受信から反応クリップ再生まで **15 秒以内**（fal 経路） | H3 Max は 5 秒クリップ約 3 秒。残りは転送・キュー |
| 待機の継ぎ目 | 待機ループ間、待機→反応→待機の切替で黒や停止を出さない。クロスフェード 300ms | 「常時いる」が崩れると人形以下になる |
| 顔一貫性 | 参照セット 3 枚で「同じ人に見える」を主観 5 段階で 4 以上（1 週目に 20 本で実測し公開） | 成立しなければ §9 の設計変更 |
| 解像度・長さ | 480p・5 秒既定。反応クリップは最大 10 秒 | 費用 |
| 費用 | **反応クリップ**：r2v $0.08/秒＋参照画像 $0.02/枚 ＝ 5 秒・3 枚で **$0.46**。30 秒間隔 60 分で約 $55。**待機プール**：12 本で約 $5.5、ローカルなら $0。1 配信の上限額を設定可、到達で反応のみ停止（待機は続く）。単価は fal 公式 2026-09 確認 | 連続生成（$330/時）は不可能。二層で吸収 |
| ローカル経路 | 待機プールの生成に最適（時間はかかるが無料）。反応クリップは RTX 4090 で約 50 秒、事前生成モード扱い | fal 公式が同種機能を出したときの主戦場 |
| 可用性 | fal エラー時は待機ループを続ける。配信は止めない | 配信中断が最大の失敗 |
| API クォータ | YouTube 1 日 10,000 unit 内。`pollingIntervalMillis` 準拠 | 変更なし |
| セットアップ | `git clone` → `.env` → 1 コマンド起動 → 顔ガチャ → OBS に URL。**推し作成から配信まで 10 分** | 「誰でも手軽に」の定量定義 |
| 推しの可搬性 | 推し 1 体 ＝ `data/personas/<id>/` フォルダ（persona.json、参照セット、声、待機プール）。コピーすれば別マシンで同じ推し | ホスト型への移行と共有のため |

## 6. アーキテクチャ

```
[推し作成 UI]──▶ persona/  顔ガチャ・参照セット派生・声サンプル・人格 ──▶ data/personas/<id>/
                                                                        ├ persona.json
[YouTube Live]                                                          ├ refs/ face.png full.png scene.png
      │ chat                                                            ├ voice.wav
      ▼                                                                 └ idle/ 01.mp4 … 12.mp4
[Server（Node.js / TypeScript）]
  ├─ chat adapter        （youtube / manual）                 ✅
  ├─ filter / selector   （NG・実在人物・レート・承認）        ✅
  ├─ reply（任意）       （LLM が推しの一言を返す）            新規
  ├─ prompt builder      （世界観＋参照＋人格＋コメント＋台詞）✅ 拡張
  ├─ backend: fal | local | mock                              ✅
  ├─ idle pool           （待機プールの生成と供給）            新規
  ├─ queue / budget                                           ✅
  └─ metrics logger（JSONL）                                  ✅
      │ WebSocket
      ▼
[Overlay（静的 HTML/JS）] ← OBS ブラウザソース
  ├─ 下層：待機ループ（video 要素 2 本でクロスフェード）
  └─ 上層：反応クリップ＋投稿者名＋台詞字幕＋「AI 生成」
[Config UI（同一サーバー）]
```

- **設計原則：ドメイン非依存**は維持。「入力 → フィルタ → （返事）→ 合成 → 生成 → 二層再生」の配管であり、推し活固有の前提はプロンプトと UI 文言に閉じ込める。ライブコマース・受付・語学は同じエンジン
- **推しはフォルダ**。サーバーの状態はメモリ、永続化は JSONL ログと `data/personas/`
- 言語 TypeScript（Node）。画像生成・TTS も fal の HTTP 経由。ローカル ComfyUI は HTTP
- ライセンス MIT。ホスト型を作るときもエンジンは MIT のまま

## 7. 安全性・運用ルール

1. **顔はアプリ内生成のみ**。写真・URL からの推し作成は UI に置かない。開発者向けの `.env` パス指定は残すが README で「自分で生成した架空の顔に限る」と明記
2. **実在人物の生成禁止**：コメント側の人名・敬称・@・肩書の無条件除外は継続。顔ガチャの生成プロンプトにも「実在の人物・有名人に似せない」を固定で入れる
3. **未成年に見える推しを作らない**：顔ガチャの生成指示を成人に固定し、生成物の確認画面で警告。性的表現のブロックは既存どおり二重
4. **声は TTS 生成のみ**。実在人物の音声からのクローンは不可
5. **AI 使用の明示**：オーバーレイに「AI 生成」を既定 ON。YouTube の合成コンテンツ開示を README の配信手順に含める
6. **配信者（推しの持ち主）が主導**：ON/OFF・世界観・レート・承認・返事モードは持ち主が決める
7. 個人プロジェクトとして運営する

## 9. リスク

| リスク | 対処 |
|---|---|
| 参照 3 枚で顔が保てない | 末尾フレーム連結を MVP に繰り上げ。それでも駄目なら「待機はリップシンク（MuseTalk）、反応だけ生成」の折衷に設計変更。1 週目の実測で判断 |
| fal H3 Max で台詞・声が出ない | 返事は字幕＋別 TTS で音声だけ重ねる。映像は無音生成。ローカル H3（ネイティブ音声）を待つ |
| 費用が想定を超える | 480p・5 秒固定、待機はローカル生成、反応は 30 秒以上の間隔、上限で反応停止 |
| ディープフェイク製品と誤解される・悪用される | 顔はアプリ内生成のみ、実在人物・未成年の禁止、AI 明示。README の最上部に書く。写真アップロードの要望には応えない |
| プラットフォーム規約（YouTube の合成コンテンツ、なりすまし） | 配信手順に開示手順を含める。推しの説明欄テンプレを用意 |
| fal 公式や他者が「生成型アバター配信」を先に出す | 主資産は「推し 1 体の実運用映像と実測」。**転換の閾値**：fal 公式が参照付きの常時アバター配信を出したら、ローカル H3・LoRA・日本語推し活運用に軸足を移す |
| 待機と反応の継ぎ目が不自然で「人形以下」になる | 待機プールの末尾と先頭を同じ姿勢で生成（プロンプトで固定）、クロスフェード、反応クリップの先頭に待機の姿勢を指定 |
| 並走プロジェクトの増加 | 6 週間で終わる投資と定義。延長は Corecord 側に統合する形でのみ |

| 項目 | v0.6 | v0.7 |
